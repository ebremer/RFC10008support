## Cross-cutting: redirect semantics (§2.5)

A recurring failure class, independent of language: clients that treat QUERY like POST on 301/302 and silently downgrade it to GET, discarding the query body.

| Stack | Status | Tracking |
|---|---|---|
| Guzzle | ✅ Fixed | [PR #3702](https://github.com/guzzle/guzzle/pull/3702) — merged (+8) |
| Go (net/http) | ✅ Fixed | [Issue #80488](https://github.com/golang/go/issues/80488) — closed completed (+64) · [CL 803520](https://go.dev/cl/803520) landed |
| Apache HttpClient 5 | ✅ Released | part of [PR #840](https://github.com/apache/httpcomponents-client/pull/840) (+15); in 5.7-alpha1 (+58) and 5.7-beta1 (+128) |
| async-http-client | ✅ Released | [PR #2317](https://github.com/AsyncHttpClient/async-http-client/pull/2317) — merged (+81), in 3.0.14 (+100): QUERY and its body survive 301/302/307/308; a 303 becomes GET |
| query-go-sdk / http-query (Rust, Dart) | ✅ By design | §2.5-conformant redirect handling added in the +49 releases |
| libwww-perl | ⚠️ Open | [Issue #530](https://github.com/libwww-perl/libwww-perl/issues/530) (+35) — `HTTP::Message` knows QUERY (+38) but `LWP::UserAgent` still downgrades on 302 |
| requests | ⚠️ Acknowledged | maintainer calls the caveat "relatively trivial to handle", but no first-class API is planned yet ([#7574](https://github.com/psf/requests/issues/7574), +23) |

Worth checking explicitly in any stack marked "✅ Generic" above — arbitrary-method support does not imply correct redirect handling.
